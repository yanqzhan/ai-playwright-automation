# AI + Playwright 智能自动化测试平台

基于大语言模型 + Playwright 打造的智能测试自动化工具，彻底解决传统自动化脚本编写成本高、维护困难、排障耗时的痛点。支持自然语言生成脚本、智能元素定位自愈、自动故障分析、语义断言等核心能力，同时兼容云端大模型与本地 Ollama 私有化部署。

## ✨ 核心特性

### 1. 自然语言转测试脚本
- 直接输入业务需求（如「登录系统，新建一条工单」），AI 自动输出完整可运行的 Playwright Python 代码
- 自动提取页面 DOM 元素，优先生成 `role`、`text`、`label` 等稳定语义选择器，规避脆弱的 XPath / 随机 ID
- 自动补充等待逻辑、异常捕获、基础断言，无需从零编写样板代码

### 2. 智能元素定位与自愈（核心价值）
- DOM 语义定位优先，视觉识别兜底的混合定位策略，前端样式微调不影响脚本运行
- 元素定位失败时，AI 自动分析当前页面，重新生成选择器并重试执行，减少人工维护成本
- 自动识别弹窗、Toast、Loading 状态，智能插入等待时机，无需人工硬写 `wait_for_selector`

### 3. 自动故障分析与修复建议
- 自动解析 Playwright Trace 文件、截图、错误栈
- AI 智能分类失败原因：产品 Bug / 网络抖动 / 时序问题 / 选择器失效 / 断言不匹配
- 自动输出可落地的修复建议，支持不稳定用例（Flaky）自动检测与原因归类

### 4. 语义化智能断言
- 无需硬编码文本、数值，用自然语言描述断言即可
- 支持业务级断言：「页面是否展示成功提示」「列表是否新增一条数据」
- 适配文案频繁变更的系统，断言不再随文案修改而失效

### 5. 低代码无代码模式
- 业务人员、手工测试人员无需掌握 Playwright API
- 用自然语言描述操作步骤，即可直接驱动浏览器执行自动化
- 降低自动化使用门槛，扩大自动化覆盖范围

### 6. 边界用例自动生成
- 基于页面表单元素自动补充异常场景：空输入、超长文本、非法格式、特殊字符
- 批量生成边界测试脚本，提升用例覆盖度

### 7. 双模式一键切换
- 云端模式：接入商用大模型，效果最优，开箱即用
- 本地模式：对接 Ollama 私有化部署，数据不出内网，零调用成本

## 🛠️ 技术栈

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| UI 客户端 | Streamlit | 纯 Python 构建 Web 交互界面，开发效率高 |
| 自动化核心 | Playwright Python | 官方原生 Python 版本，支持全浏览器自动化 |
| AI 能力层 | OpenAI 兼容协议 | 同时支持云端大模型与本地 Ollama |
| DOM 处理 | BeautifulSoup4 + lxml | 页面元素提取与解析 |
| 工具库 | python-dotenv、Jinja2 | 配置管理、报告生成 |

## 📦 快速开始

### 环境要求
- Python 3.10 ~ 3.12（推荐 3.11 稳定版）
- 至少 4GB 可用内存（本地模型需根据模型参数提升显存）

### 1. 项目部署
按项目目录结构创建所有文件，或克隆项目到本地。

### 2. 安装依赖
```bash
# 安装 Python 依赖
pip install -r requirements.txt

# 安装 Playwright 浏览器内核
playwright install chromium
```

### 3. 配置环境变量
复制 `.env.example` 为 `.env`，根据使用场景选择配置：

#### 云端大模型模式（推荐新手使用）
```env
USE_LOCAL_OLLAMA=false
LLM_API_KEY=你的API密钥
LLM_BASE_URL=
LLM_MODEL=
VISION_MODEL=
```

#### 本地 Ollama 模式
```env
USE_LOCAL_OLLAMA=true
OLLAMA_BASE_URL=http://localhost:11434/v1
OLLAMA_LLM_MODEL=qwen3.5:9b
OLLAMA_VISION_MODEL=llava:7b
OLLAMA_API_KEY=ollama
```

> 本地模式需先安装 Ollama 并拉取对应模型：
> ```bash
> ollama pull qwen3.5:9b
> ollama pull llava:7b
> ```

### 4. 启动项目
```bash
streamlit run app.py
```

启动后浏览器自动打开 `http://localhost:8501` 即可使用。

## 📖 使用指南

### 1. 脚本生成工作台
- 输入目标页面 URL、自然语言操作需求、脚本名称
- 点击「生成脚本」，AI 自动分析页面并输出完整 Playwright 代码
- 同步自动生成 3 组边界用例，可直接扩展测试场景

> 推荐测试地址：`https://demo.playwright.dev/todomvc/`
> 示例输入：`在待办输入框中输入“测试自动化”，按回车提交，然后标记为完成`

### 2. 测试执行中心
- 选择已生成的脚本文件，点击执行
- 自动录制 Trace 文件，捕获执行全过程
- 支持稳定性检测：自动重试 3 次，识别 Flaky 不稳定用例

### 3. 故障分析
- 脚本执行失败后，自动保留错误信息与 Trace 文件
- 点击「AI 分析」，自动输出失败类型、原因分析、修复建议
- 支持手动上传 Trace.zip 文件进行离线分析

### 4. 语义断言
- 输入测试页面 URL 和自然语言断言描述
- AI 自动提取页面文本，语义判断断言是否成立
- 示例断言：`页面显示操作成功提示`、`待办列表新增了一条数据`

### 5. 低代码模式
- 输入目标页面 URL，每行描述一步操作
- 无需编写代码，AI 自动解析步骤并驱动浏览器执行
- 适合业务人员快速验证场景

## 📝 注意事项
1. 本地开源小模型在复杂代码生成、逻辑推理上效果弱于云端商用模型，简单场景可正常使用
2. 视觉定位为兜底方案，准确率低于 DOM 语义定位，优先保证页面元素语义属性完整
3. 项目为演示版本，执行脚本采用 `exec` 方式实现，生产环境建议改用子进程隔离执行
4. 建议优先使用语义化标准的测试页面，脚本生成与定位效果最佳
